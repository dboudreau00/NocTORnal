Analyst sign-in

Six digits from your authenticator app, or a recovery code (xxxxx-xxxxx-xxxxx) if the app cannot produce one that works. You issue your own recovery codes from Account (your name, top right) while signed in. With neither, an administrator can re-enrol your authenticator.

The matrix

A cell is how one piece of evidence stands against one hypothesis. H1, H2 and so on number the hypotheses in the order they were written, and a number stays with its hypothesis whatever the ranking does. Each row names what its evidence is about and what it claims, with the Admiralty grade and the weight every cell in it counts at; the name opens it in the graph. Evidence that says the same thing about every hypothesis is kept in the record and excluded from the ranking, because it discriminates nothing, and its row is dimmed. A row with a blank cell that agrees with itself so far is unfinished, not undiagnostic: its diagnosticity reads unfinished until it is scored against the rest, and the blanks it still needs are outlined.

What this screen will and will not do

  • Metadata renders. Bytes do not. There is no preview, no hex view and no icon taken from the file. Rendering attacker-supplied bytes in the same origin as the case file is a drive-by vector into your highest-trust system, seeded with hostile files by design.
  • The filename is evidence, not a path. It is stored for the record and never used as a path component. The object key is always the SHA-256.
  • Download is a separate origin, step-up gated. It is the one action here that puts working malware on a disk. It refuses unless the request arrived at the configured sample origin, and the check lives in the service so a second caller cannot skip it.
  • The archive password is an interlock, not protection. infected is public and ZipCrypto is broken. It stops a double-click and stops a mail gateway eating the sample. Confidentiality comes from access control, transport and audit.
  • A rejected sample is preserved, not destroyed. Unless this deployment chose otherwise, rejecting moves the encrypted bytes into a separate preservation store under a legal hold and keeps the data key. Getting them back needs a Security Officer's authorisation naming the person who retrieves them, and nobody can authorise themselves. Where a deployment destroys rejected samples instead, a legal hold on the sample or its case refuses the destruction: preservation and destruction can both be legal obligations, and software does not get to pick.

Gaps, recorded rather than hidden

Fuzzy hashing (imphash, ssdeep, TLSH), YARA and sandbox detonation are not built. Each absence is written onto the sample row as a gap with a reason, because a NULL imphash reads as “this sample has no imports” and an absent one says nobody looked.
