# yara-x, by version and by the sha256 of its two Linux wheels. The Dockerfile installs it from this
# file with --require-hashes when the image is built with the yara extra, which it is by default,
# before the editable install that would otherwise fetch it unhashed. It is not in constraints.txt
# alone because a constraints file takes no hashes (pip does not apply them there); constraints.txt
# pins the same version, and test_yara_worker_default.py holds the two equal.
#
# The two hashes, one per architecture a production host builds on:
#   yara_x-<version>-cp38-abi3-manylinux_2_28_x86_64.whl
#   yara_x-<version>-cp38-abi3-manylinux_2_28_aarch64.whl
# yara-x has no dependencies, so --require-hashes needs this one entry. CI's Pinned images resolve
# job downloads both wheels with the hashes required.
#
# To move it: read https://pypi.org/pypi/yara-x/<version>/json, take `digests.sha256` of the two
# files named above, write the version and both hashes below and the version in constraints.txt,
# run the suite, build the image, and commit the two files together.
